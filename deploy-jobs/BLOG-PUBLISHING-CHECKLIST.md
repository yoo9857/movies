# Blog publishing checklist

The workflow used on 2026-08-07. Keep the prose and image jobs in
`deploy-jobs/` so a post can be reconstructed without editing database rows.

## 1. Pick and verify the subject

- Prefer a same-day story with at least two independent reports.
- Use the original outlet or a trade publication as the primary source.
- Preserve the reported status. “Eyed”, “circling” and “in talks” are not
  “cast” until the studio or representative confirms it.
- Write an angle rather than a rewritten news report. Put every factual claim
  that matters in the `sources` list.

## 2. Prepare the draft job

Create `deploy-jobs/<topic>-draft.json` with title, dek, Markdown content,
tags, category, sources and any known person or film slugs. Check it before a
database write:

```sh
npm run db:write-posts -- --drafts=deploy-jobs/<topic>-draft.json --dry
```

The dry run proves the schema and house-language rules, and prints the slug
that every image job must target.

## 3. Build the picture list

The publication floor is **four photographs: one hero and three in the body**.

Use sources in this order:

1. Current, licensed photographs with credit, licence and source intact.
2. A YouTube thumbnail chosen by an operator after opening and inspecting it.
3. X or Instagram posts as official embeds only.

Rules:

- Never copy an X or Instagram photograph into site storage. Use an
  `"embed": true` body job so the platform serves the post with its author.
- A YouTube thumbnail is allowed only after a person checks the image. Keep
  the channel credit and video source generated by `fill-post-images.ts`.
- Reject fan art, synthetic casting mock-ups, unrelated people, watermarks
  that obscure the subject, and several crops of the same photograph.
- Write alt text from what is visibly in the image, not from the video title.
- Spread three body images across exact `##` headings with `"at"`; do not
  append a gallery to the end of the article.

## 4. Create the draft and place images

On production, after the reviewed job files are present:

```sh
export PATH=$HOME/.nvm/versions/node/v22.19.0/bin:$PATH
cd ~/cinepixo
npm run db:write-posts -- --drafts=deploy-jobs/<topic>-draft.json

cd apps/web
npx tsx scripts/fill-post-images.ts \
  --post=<slug> \
  --youtube=<reviewed-video-url> \
  --alt="<what the hero visibly shows>"

npx tsx scripts/fill-post-images.ts \
  --body=../../deploy-jobs/<topic>-body.json
```

Licensed hero jobs use `--url`, `--credit`, `--license`, `--license-url` and
`--source-url` instead of `--youtube`.

## 5. Refuse a broken or thin post

Fetch every stored object before publication:

```sh
cd ~/cinepixo/apps/web
npx tsx scripts/blog-doctor.ts --post=<slug> --fetch
```

Expected result: four pictures, zero errors and zero warnings. The publish
command independently refuses anything without one hero and three body
pictures. `--allow-few-pictures` is for an explicit editorial exception, not
a shortcut.

## 6. Publish and verify the public page

```sh
npx tsx scripts/publish-post.ts <slug>
curl -L -s -o /tmp/post.html -w "%{http_code}\n" \
  https://cinepixo.com/blog/<slug>
```

Confirm:

- HTTP 200;
- no `noindex` in the public HTML;
- all four image objects appear;
- `publish-post.ts` reports a successful IndexNow submission.
