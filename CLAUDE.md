# CinePixo — project notes for agents

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

English-language fandom site for film-critic fans (reviews, ratings, critic profiles). See README.md for stack and commands.

- Monorepo: npm workspaces. `apps/web` (Next.js 16, Turbopack), `packages/db` (Prisma 7 + `@prisma/adapter-pg`), `packages/shared` (zod schemas).
- **Next.js 16 has breaking changes** — read `node_modules/next/dist/docs/` before writing Next code (see apps/web/AGENTS.md). Notably: `proxy.ts` not `middleware.ts`; `cookies()`/`params`/`searchParams` are async.
- **Auth is enforced in `apps/web/src/lib/auth.ts` (DAL)**, called inside every protected route handler and admin layout. Never rely on proxy.ts for security.
- All API input goes through zod schemas in `packages/shared`. Mutating routes must call `requireSameOrigin(request)`.
- **The CSP is built per request in `proxy.ts` from `lib/csp.ts`, not in `next.config.ts`** — `script-src` is `'nonce-…' 'strict-dynamic'` and names no host, because AdSense supports only strict CSP ("the domains the ad code uses change over time"). A host allowlist there fails silently: the ad, then Google's consent message, simply never load. Anything emitting a `<script>` server-side must carry `headers().get("x-nonce")` (`JsonLd`, `AdSenseScript`), and the ad slot's shared constant lives in `lib/site.ts` because `AdSlot` is a client component and must not import a module that touches `next/headers`. `test/csp.test.ts` pins the shape.
- **PostgreSQL 18 is the only database** — there is no SQLite fallback (removed 2026-07-30). `ops/postgres/README.md` covers the container, pool budget, timeouts, retry classification and backups; read it before touching anything database-shaped.
- `Review.status` / `User.role` are real PG enums (`ReviewStatus`, `UserRole`); list columns are native `text[]`; every timestamp is `timestamptz`. Constraints Prisma cannot express (CHECKs, `LOWER()` unique indexes, trigram indexes) live in hand-written SQL in `prisma/migrations/*_constraints`.
- Prisma client is generated to `packages/db/src/generated` (gitignored). After schema changes: `npm run db:migrate` then `npm run db:generate`.
- `npm run db:*` reads `apps/web/.env.local` via `packages/db/prisma/env.ts` — real environment variables win over the file, so an exported `DATABASE_URL` still points at a scratch database.
- **SEO/GEO lives in `apps/web/src/lib/seo.ts`** — see the README section. Page metadata goes through `pageMetadata()` (never hand-rolled, or canonicals drift); structured data goes through `graph()` + `<JsonLd>` (one `@graph` per page, `@id`-linked). Never emit a rating, date or count that isn't rendered on the page.
- Keep `npm audit` at 0: patched transitive versions are pinned in root package.json `overrides`.
- **Tests**: `npm test` (unit, no database) and `npm run test:db` (PostgreSQL constraints, needs `DATABASE_URL`). Config in `vitest.config.ts` as two projects. The DB suite builds a throwaway `*_test_*` database from the real migration files, so a new hand-written constraint should get a test in `packages/db/test/constraints.db.test.ts` alongside it.
- Optional prose fields use `optionalText()` in `packages/shared` so `""` becomes `undefined` — the columns are nullable and `verdict ?? excerpt` fallbacks depend on it. Don't reintroduce `.optional().or(z.literal("")...)`; its right-hand side is unreachable.
- `ReviewBody`'s remark plugins include `remark-cjk-friendly` (+ its gfm-strikethrough twin). They are load-bearing: without them `**기생충!**은`-style emphasis (punctuation then a particle) renders as literal asterisks. Tests in `apps/web/test/review-body.test.tsx` pin this. The visual editor's markdown parser needs the same repair — `editor/cjk-emphasis.ts`, pinned by `roundtrip.test.tsx`.
- **Missing slugs on streamed pages answer 200, not 404 — by framework design.** Once the shell streams the status is committed; Next injects `<meta name="robots" content="noindex">` instead, and that is the sanctioned mitigation (verified in output). Don't burn time chasing a real 404 on a dynamic page; route handlers (the `.md` endpoints, `/legacy/movies`) are where real status codes live. `htmlLimitedBots` in next.config controls *metadata placement* for scrape-once bots, not status codes.
- **Share cards are generated per segment** (`opengraph-image.tsx` + `lib/og-card.tsx`). Three hard-won rules: file-based OG images do **not** inherit into child segments (each listing re-exports `lib/og-site-image.tsx`); every glyph must exist in Geist because satori has no fallback chain (the star is drawn SVG, ellipsis is `...`); and **satori cannot decode WebP**, so our own images go through `ourImageAsPng()`. Never pass `images` to `pageMetadata` on a page that has a card — and never set `images: undefined`, which suppresses the convention entirely.
- **People are enriched from Wikimedia, not TMDB** (`lib/wikimedia.ts`, no API key). Facts (dates, birthplace, occupations, Q-id, IMDb id) are imported fill-only; the photograph is imported **with its credit and licence**, which the page must render; the article extract is returned as a draft and **never written to `bio`** (CC BY-SA, and the prose is meant to be ours).
- **`Person` is the site's own entity**, not a TMDB mirror: `MovieCast`/`MovieCrew` point at it via `personId`. `Person.image` is always **our** object (uploaded through `lib/media/`), never a TMDB URL — `tmdbProfilePath` is only an import source. `PersonPortrait` is the one place a face renders: our image → unimported TMDB path → house monogram. Photos come in via `POST /api/v1/admin/people/[id]/photo` (file or URL) or the batch `…/people/photos/import`.
- **Movie URLs are slugs** (`/movies/parasite-2019`), minted once (import/seed) and never rewritten on refresh — the URL is the film's public identity. Old cuid URLs answer a real 308 via `next.config.ts` rewrite → `app/legacy/movies/[id]/route.ts`; a redirect thrown in the page cannot set the status because Next streams metadata (200 is already on the wire).
- The review editor's default Write tab is Tiptap (`components/review/editor/`), serializing to markdown on every edit — markdown stays the storage format. Round-trip safety (open → save ⇒ same rendered page) is held by `roundtrip.test.tsx` against `richExtensions()`; extend that list and the test together.
- Review images upload via `POST /api/v1/my/review-images` through the hardened pipeline in `lib/media/` and land in the markdown as `![alt](url)`. Objects are never deleted when text stops referencing them — orphans are cheap, GC is not.
- **The library is fed from Wikidata, keyless** (`db:import-wikidata` and friends; TMDB import exists but no key is configured anywhere). The film query matches `P31` against an **explicit type list** (film, animated film, animated feature film, anime film, silent film) — never `P31/P279*`, which drags in TV films, episodes and unmade "film projects", and never bare `Q11424`, which is how all of Pixar silently missed a 115k-film library (fixed 2026-08-01). Every import script is a fill-only, idempotent pass; the dependency order for new rows is import → credits → people facts (stores the `wikipediaUrl` every later pass selects on) → portraits/posters/synopses.
- **Bulk filling runs as "lanes" on the prod server** (`~/lane-*.sh` via nohup, logs in `~/fill-logs/`), 3–4 concurrent at most or the app sees query timeouts. Most passes snapshot their queue at start-up, so a film imported later is invisible to a running pass and needs a fresh run; only the poster lane loops until dry.
- **Video files we host**: `Movie.trailerFile` (a trailer) and `Movie.filmFile` (the whole picture, when it is free) each carry `*Credit/License/LicenseUrl/SourceUrl/Duration` columns. CHECKs allow only our origin (`^/`) or the pokemon-dive bucket's `cinepixo/` prefix — a hotlink is refused by the database — and a licence without its source is refused (operator uploads state no licence, so they stay legal). The film page renders our `trailerFile` first (`FreeFilmPlayer`), the `MovieVideo` gallery independently of it, and the YouTube embed only when neither exists; `/watch` is the listing that surfaces hosted files (nothing else does — these are mostly unreviewed films no rail picks up). Commons video downloads take the 480p/240p **transcode**, never the original (archival masters, ~500 MB for a 5-minute reel).
- **The blog is `/blog` ("Off Camera"), and it is editorial — admin-only, no rating column.** A `Review` argues about one film and is scored; a `Post` is what a review has no room for (a person off camera, an argument, craft, a watchlist). Five `PostCategory` shelves at `/blog/category/<slug>`; posts stay flat at `/blog/<slug>` because a slug is the piece's identity and must not move when it is recategorised (`RESERVED_POST_SLUGS` keeps a post off the shelf prefix). `PostPerson`/`PostMovie` are the point of it: a post links to our person/film pages and those pages list the post — see the reciprocal blocks on both.
- **`Post_claims_are_sourced` is the load-bearing constraint of the blog.** A `PEOPLE` or `ISSUE` post cannot reach `PUBLISHED` with an empty `sources` array, because it is a factual claim about someone who can be harmed by our getting it wrong. `SOURCED_CATEGORIES` in `packages/shared` names the same two and the zod `.refine()` turns the violation into a message on the right field; the page, the `.md` rendition, `feed.json` and `llms.txt` all print the URLs. A citation the database demands and a surface hides is a lie told to the schema — keep all five in step.
- **`Post_image_needs_alt`**: a hero must say what it shows, blank included — `alt=""` reads as "decorative, skip this", which over a photograph of the piece's subject deletes them for the reader who most needs them named. Note the shape: `image IS NULL OR (imageAlt IS NOT NULL AND imageAlt ~ '[^[:space:]]')`. The `IS NOT NULL` is **not** redundant — a CHECK passes when its expression is NULL, and `NULL ~ '…'` is NULL, so the regex alone rejected a blank caption and admitted a missing one.
- **`npm run deploy-check -- --url=<site>` after every deploy.** A health endpoint proves the app is up, not that it is right. The failure it exists for: `NEXT_PUBLIC_GOOGLE_ADSENSE_ACCOUNT` is **inlined at build time**, so a build that ran without `apps/web/.env.local` bakes an empty publisher id — `/ads.txt` then answers 404 and the ad code renders nothing, silently, until AdSense reports the file missing and the review stalls. It also pins robots, both sitemaps, all three feeds, llms.txt and the IndexNow key.
- **IndexNow tells Bing, Yandex, Seznam and Naver a URL changed** (`lib/indexnow.ts`, key served from `INDEXNOW_KEY` at `/indexnow-key.txt`). `publish-post` submits the piece, `/blog` and its shelf on publish, and `--ping` resubmits an already-live piece after an edit. **Google is not a participant and cannot be** — the Indexing API is restricted to job postings and livestreams, the sitemap ping was retired in 2023, so Google's levers are the sitemap in robots.txt, links from pages it already has (a post's subjects link to it), and Request Indexing in Search Console. The script says so rather than letting a green line imply otherwise.
- **`npm run blog-doctor [--fetch] [--post=<slug>]`** is the checks a constraint cannot make: whether every picture a post points at actually loads, whether each carries alt text and its licence's source, whether a published claim about a person kept its citations. Born from the storage-prefix bug — the PUTs succeeded, the URLs were well-formed, the CHECK passed, and all seven images 404'd, because what was wrong was the relationship between two systems rather than a value in either. Run it with `--fetch` after any image work.
- `btrim(x) <> ''` does **not** mean "not blank": one-argument `btrim` removes spaces only, so a body of newlines passed `Post_content_meaningful` until a constraint test caught it (fixed 2026-08-06, `*_blank_text_is_not_content`). Use `x ~ '[^[:space:]]'`.
- **`db:write-posts` lands drafts, not posts.** `--sources=<json>` (a list of `{sources, category, brief?, angle?, people?, films?}`) generates a piece through `codex exec` and writes it as `DRAFT`; `--drafts=<json>` publishes prose written elsewhere through the same checks; `--publish` opts into going live. The default is a draft because `Post_claims_are_sourced` can prove a citation exists but nothing in a database can prove the prose is faithful to it — that check is a person reading both. **`brief` is the load-bearing field**: Naver and the Korean outlets syndicated through it refuse an automated fetch from some clients, so an operator pastes the facts and the URL stays as the citation. (Node's `fetch` does get through where the harness `WebFetch` tool does not — verified 2026-08-06.) `codex` is installed on the server only, so generation runs there.
- **Post heroes are a separate fill pass**: `npm run post-images` (`apps/web/scripts/fill-post-images.ts`, wired like the other web media scripts — it needs `lib/media/`, which `packages/db` cannot import). `--auto` fills image-less posts from **licensed material only**: a linked person's Commons photograph (full provenance via `wikimedia.ts`), else their portrait or the linked film's artwork already in our bucket (reused by URL — never delete a post hero, it may be a person's portrait). Operator jobs (`--images=<json>`, or `--post=<slug>` with `--url|--youtube|--file|--capture=<film-slug>`) additionally crawl a page's `og:image`, rehost a YouTube thumbnail (credited to the channel via oEmbed, `sourceUrl` = the watch URL), or ffmpeg-capture a frame from `trailerFile`/`filmFile` (inherits the file's licence columns; ffmpeg is required only for capture). The bare `--youtube` flag lets `--auto` also use a video already cited in `sources` — an operator opt-in, because a thumbnail is not licensed to us. **Instagram is refused by name** (login-walled and unlicensed); with permission, save the file and pass `--file` with the post URL as `--source-url`. Pure URL parsing lives in `lib/post-image-sources.ts`, pinned by `test/post-image-sources.test.ts`. `--body=<json>` runs the same jobs into the **markdown** instead of the hero columns — each image lands as `![alt](url)` with a `*Photo: credit · licence · source*` line under it, and a job with `"embed": true` lands as the bare post URL; `--heading=` writes one `##` above whatever is appended. A job's `"at": "<heading text>"` places it above that `##` (an `at` matching no heading throws rather than silently appending), and **jobs sharing one `at` become one row**, so a piece can run 1 / 2 / 2 / 1 down the page. Two pictures by the same hand under the same licence share one credit with numbered source links.
- **The blog's `VOICE` is a staff writer who is also a fan** (`write-posts.ts`), not a neutral summarizer: warm, specific, first person where it is true, no invented consensus. It carries a **BANNED list** — `through-line`, `delve`, `landscape`, `testament`, `showcase`, `resonate`, `iconic`, `moreover`, `not just X but Y`, `serves as`, rhetorical-question transitions and the rest — because each is a phrase reached for when there is nothing to say, and forbidding them forces a real sentence into the gap. The four critics' review voices are separate and unaffected.
- **A photo credit is a caption, not a sentence of the piece**: `*Photo: …*` / `*Photos: …*` as a lone emphasis paragraph is recognised by `ReviewBody` and set in `.cx-credit` (0.72rem, muted, quiet underlines) — at body size the accent-coloured licence links pulled the eye out of the argument. The hero's `figcaption` wears the same class so every credit on the site is one size. Pinned in `review-body.test.tsx`.
- **Two or more images in one markdown paragraph render side by side** (`ReviewBody`'s `p` override → `sm:grid-cols-2`); one stays full width. Heights are not cropped to match — a tidy grid is not worth slicing the top off a face. Pinned in `review-body.test.tsx`.
- **Gathering is topic- or person-driven, newest first.** `npm run topic -- --topic="…"` pulls the latest coverage (Bing News RSS, en-US market pinned, bing-redirects unwrapped, one article per outlet) plus the newest licensed Commons photographs (relevance search re-sorted by capture day; `--image-query=` when the story's phrasing isn't a photo's), verifies a `--youtube=` video via oEmbed, and emits a write-posts sources job and/or a `--body` jobs file — the operator reviews both; `brief` is never auto-filled. `npm run person-photos -- --person=<slug>` walks the person's P373 category tree (depth 2), sorts by capture date, caps two frames per event. `commonsCaptureDay` in `lib/post-image-sources.ts` pins the messy `DateTimeOriginal` parsing. X and Instagram are refused by name in both: anonymous reads are walled and nothing there is licensed — permission-in-hand photos come in via `post-images --file`.
- **`npm run save-media` is a personal archive, not part of the site** (`apps/web/scripts/save-media.ts`): it writes to a local folder with a `.json` sidecar per file and touches neither the upload pipeline nor the database. YouTube's poster frame comes from the public oEmbed/thumbnail endpoints; X and Instagram are **delegated to yt-dlp / gallery-dl** rather than scraped here — those tools track platform changes and carry the operator's own cookies. Private copying and publishing are separate acts under separate rules, which is why they are separate programs: attribution is not a licence, and `Post_image_license_has_source` still refuses an unlicensed file.
- **A paragraph that is nothing but a pasted URL embeds**: YouTube → `VideoEmbed` (click-to-load nocookie frame split out of `TrailerEmbed`), an X status or Instagram post → `SocialEmbed` via the platform's own embed endpoint (`platform.twitter.com/embed/Tweet.html`, `instagram.com/p/<code>/embed`) — showing a post is sanctioned, copying its picture out is not. CSP `frame-src` names exactly these hosts; all frames load on click only. A written link (`[words](url)`, or a URL inside a sentence) stays a link, and the Tiptap round-trip's `[url](url)` form still embeds because the test is text === href — pinned in `review-body.test.tsx`; URL parsing pinned in `post-image-sources.test.ts`.
- A blog draft is readable at its own URL by an admin (`isAdmin()` in `lib/auth.ts`, not `requireAdmin`), marked `noindex`, counted in no view total and emitting no `BlogPosting` node. Everything else — shelves, sitemap, feeds, `.md`, share card — keys on `PUBLISHED`.
- In JSON-LD, `VideoObject.uploadDate` is a schema.org **DateTime** — use `isoStamp()`, never `isoDay()`; a bare date drew two Search Console warnings (tests pin this in `seo-graph.test.ts`). A hosted trailer is described by `contentUrl` on our origin, not by a YouTube `embedUrl` the page no longer renders — the graph follows the page.
